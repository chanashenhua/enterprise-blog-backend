# 动态知识首页 API

## 查询首页信息流

`GET /api/articles/feed?limit=6`

请求必须经过网关并携带当前用户上下文。`limit` 表示每个分区最多返回的文章数，默认 6，最大 20；小于等于 0 时使用默认值。

响应包含三个分区：

- `latest`：按最近发布时间倒序排列的可见文章；
- `popular`：根据阅读、点赞和收藏排名排列，互动数据不足时用最新文章补齐；
- `subscribed`：分类或标签命中当前用户订阅的最新文章；
- `generatedAt`：本次聚合完成时间。

每篇文章包含 `articleId`、作者、标题、摘要、分类、标签、发布时间，以及阅读、点赞和收藏数量。接口只查询 `PUBLISHED` 状态，并逐篇调用统一权限策略校验部门或团队可见范围，不会把无权阅读的标题、摘要或统计数据返回给客户端。

## 聚合与降级

- 文章主体和发布时间来自文章服务 PostgreSQL 数据；
- 热门排名通过统计服务内部接口获取；
- 当前用户订阅通过通知服务获取；
- 统计服务暂时不可用时，`popular` 自动回退为最新文章；
- 通知服务暂时不可用时，`subscribed` 返回空列表；
- 权限服务异常时请求失败，不进行放宽权限的降级。

统计服务内部接口为 `GET /internal/stats/article-rankings`，仅供文章服务使用，双方通过 `INTERNAL_FEED_TOKEN` 校验。开发环境未显式配置时使用相同的本地默认值；生产环境必须设置独立随机值。
