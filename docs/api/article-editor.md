# 文章正文、草稿自动保存与安全预览

更新时间：2026-09-30。

## 正文格式

草稿创建、草稿更新、文章读取及内容版本接口继续使用 `contentJson` 字符串字段；正文存储格式不变。本模块通过 V8 迁移增加文章修订号，见下文。
新编辑器使用以下 JSON 作为字符串内容：

```json
{"type":"markdown","version":1,"source":"## 标题\n\n**重点**与正文\n"}
```

`source` 原样保存，保留缩进及末尾换行。Markdown 采用 CommonMark 核心语法，支持标题、列表、引用、强调、链接、行内代码和围栏代码块；暂不包含表格等扩展。

旧的 `type: doc`、`paragraph`、`text` 格式继续由原渲染器处理。员工端打开旧文章时使用纯文本模式，只有作者主动切换才转换为 Markdown。未知格式、未知 Markdown 版本及非法 JSON 拒绝处理，避免静默覆盖原文。

## POST /api/articles/preview

使用与保存正文相同的投影逻辑，不产生草稿、版本、Outbox 或数据库写入。需要 Gateway 转发的已认证用户，且角色包含 `AUTHOR` 或 `ADMIN`。

请求：

```json
{"contentJson":"{\"type\":\"markdown\",\"version\":1,\"source\":\"## 标题\\n\\n正文\"}"}
```

响应：

```json
{"renderedHtml":"<h2>标题</h2>\n<p>正文</p>","plainText":"标题\n正文"}
```

纯文本投影中的空白由渲染器生成，仅用于展示摘要和检索；编辑必须读取 `contentJson` 中的源文，不能用 `plainText` 反推 Markdown。

- 未认证：401；非创作角色：403。
- 非法正文：400；Markdown 源文最多 100,000 个 UTF-16 字符，`contentJson` 字符串最多 1,000,000 个字符。
- 保存草稿时标题上限为 200 个字符；预览不需要标题或分类标签。
- 原始 HTML 被转义；链接和图片的显式协议只允许 `http`、`https`、`mailto`，相对链接保留，`javascript:`、`data:` 等被过滤。
- HTML 与纯文本只由服务端生成，不接受客户端提供的渲染结果。
- 预览受现有 Gateway 认证与路由保护；不要在生产环境直接公开内部服务端口。

实现使用 [CommonMark Java](https://github.com/commonmark/commonmark-java) 0.30.0，固定版本；在其 HTML 转义和 URL 过滤选项之上使用显式协议白名单。

## 草稿创建与请求重试

`POST /api/articles/drafts` 仍要求已认证的 `AUTHOR` 或 `ADMIN`。作者取自网关用户上下文，不能由请求体指定。

```json
{
  "title": "缓存实践",
  "contentJson": "{\"type\":\"markdown\",\"version\":1,\"source\":\"## 背景\\n\\n正文\"}",
  "tagIds": [],
  "categoryId": null,
  "clientDraftId": "c4b10842-fac3-4d13-8f91-3d466c17b1b6",
  "autosave": true
}
```

- `clientDraftId` 为可选的标准 UUID 字符串。新编辑器在开始一篇新文章时生成，并在创建响应丢失、断网重试和本地恢复后继续使用同一值；收到文章 ID 后改用更新接口。
- 服务端将作者 ID 与 `clientDraftId` 一起映射为稳定文章 ID，数据库原子插入只允许创建一次。同一 UUID 在不同作者下对应不同文章，不共享正文。
- 同一作者重复创建返回已有文章的**当前**状态与正文，不用本次请求覆盖它。客户端必须核对返回内容；若已被其他窗口修改或提交，进入冲突处理，不能把旧请求误报为已保存。
- 不提供 `clientDraftId` 时保留随机创建行为，每次调用都可能创建新文章。非法 UUID 返回 400。
- `autosave` 可选，默认为 `false`。`true` 只持久化当前草稿；手动创建产生首个历史快照。若自动创建的响应丢失，随后以相同内容手动重试，会补建且仅补建一个快照。
- 重试仍执行当前身份、正文及分类标签校验，幂等键不替代权限检查。

## 修订号与更新草稿

所有 `ArticleResponse`（包括读取、创建、更新、列表和发布结果）增加：

| 字段 | 含义 |
| --- | --- |
| `revision` | 从 1 开始的正整数，表示当前文章内容及状态的修订号，用于并发检查。 |
| `updatedAt` | 服务端文章最后实际更新的时间，ISO 8601 格式；不用于并发比较。 |

`PUT /api/articles/{articleId}/draft` 请求：

```json
{
  "title": "缓存实践（补充）",
  "contentJson": "{\"type\":\"markdown\",\"version\":1,\"source\":\"## 背景\\n\\n补充后的正文\"}",
  "tagIds": [],
  "categoryId": null,
  "expectedRevision": 1,
  "autosave": true
}
```

`expectedRevision` 必填且必须为正整数；缺失、零或负数返回 400。客户端使用最近一次读写响应中的 `revision`，不能自行猜测。更新仍校验编辑权限、标题、正文、分类与标签，只允许 `DRAFT` 或 `WITHDRAWN`；撤回文章保存后重新进入 `DRAFT`。

事务内先锁定文章行，比较修订号后再更新正文、标签等关联表，防止两个窗口同时覆盖。标题、`contentJson`、标签集合或分类发生变化时修订号加 1；撤回文章转回草稿也加 1。草稿内容相同且状态未变时，不增加修订号或更新时间。

- 修订不匹配且请求内容不同，或文章已经待审、发布、删除：409，不改变内容，不新增历史版本、审核单或 Outbox。
- 旧修订请求的标题、正文、标签与分类若全部等于当前草稿，视为保存响应丢失后的安全重试，返回当前修订，不重复写入。手动重试仍会补齐尚未形成的内容快照。
- 收到 409 后暂停自动保存，保留本地编辑，读取最新文章，再由作者决定使用服务器版本或基于刚查看的修订继续提交本地内容；后一次提交仍接受并发检查。

## 发布前的并发检查

`POST /api/articles/{articleId}/submit-publish` 在原有范围字段之外必须提交 `expectedRevision`：

```json
{
  "visibilityType": "COMPANY",
  "targetOrgIds": [],
  "reviewRequired": false,
  "expectedRevision": 2
}
```

先保存当前内容，使用保存响应的修订号发布。事务内再次比较修订及 `DRAFT` 状态；存在正文变化时，同一预期修订的自动保存与发布竞态只能有一方成功，另一方返回 409，不能发布未经本次确认的新正文。正常发布或进入待审核均增加修订号，提交前按下文规则补建内容快照；权限、组织校验和审核策略沿用现有规则。

同一发布状态、可见类型与目标集合一致，且请求修订等于当前修订或其前一修订时，允许发布响应丢失后的幂等重试，不重复增加修订、快照或发布 Outbox。待审核重试保留同一审核请求 ID，并继续调用审核服务补偿创建审核单；不会绕过当前权限、组织和审核策略检查。更早的修订或不同范围仍冲突。

审核通过、退回草稿、撤回、首次删除等实际状态变化也增加修订号；重复审核回调和重复删除不增加。可见范围只在提交发布时应用，保存草稿不应用发布范围。

## 历史版本与数据库迁移

`revision` 与 `GET /api/articles/{articleId}/versions` 中的 `versionNo` 是两个独立计数：前者防止丢失更新，后者只编号不可变内容快照。

| 操作 | 当前文章 | 内容历史快照 |
| --- | --- | --- |
| 自动创建／自动保存 | 持久化完整草稿；实际变化时推进修订 | 不新增 |
| 手动创建／手动保存 | 持久化内容；无变化不推进修订 | 与最近快照不同才新增 |
| 提交发布／审核 | 推进文章状态和修订 | 提交时与最近快照不同才新增；回调不新增 |
| 同内容重试 | 保留当前修订与更新时间 | 手动保存可补齐缺失快照，不重复追加 |

快照去重比较标题、原始正文字符串、标签集合与分类，不比较渲染 HTML 或发布范围。只与最近一版去重，因此先保存 A、再保存 B、再手动恢复 A 会形成三个版本。已产生的旧历史版本全部保留。

`V8__article_draft_revision.sql` 为 `article` 增加 `revision BIGINT NOT NULL DEFAULT 1` 及正数约束；已有文章从修订 1 开始，不根据历史 `versionNo` 回推。没有新建本地恢复表，也不把浏览器恢复副本上传为额外历史。数据库持久化使用 `JdbcArticleRepository`；`ArticleMemoryRepository` 仅供非数据库单元测试，不能作为并发事务保证的依据。

兼容性要求：

- 正文格式和既有历史记录兼容；创建接口新增参数均可选。
- 更新和发布接口新增必填修订号，是写接口契约变更。旧客户端省略它会收到 400，必须与新员工端配套更新；新员工端读到缺失或非法修订号时拒绝编辑。
- 新文章服务依赖 V8 迁移。升级时先确保 Flyway 完成迁移并切换服务，再提供配套员工端；不能将缺少修订保护的旧写服务与新服务混合承接写入。
- 本次只在测试数据库验证迁移，未运行本机业务库迁移或正式部署。

## 前端行为

- 编辑／对照／预览切换；对照或预览模式在输入停止 400ms 后请求服务端，旧响应不覆盖新结果。
- 分类、标签来自现有目录接口，支持按名称或 ID 搜索；停用选项禁止新增，已有无效选择需显式移除。
- 分类接口或预览失败提供重试，保留编辑内容；预览失败不阻止独立保存。
- 标题、正文与分类标签有效后，停止输入 2 秒自动保存；请求期间继续输入的内容保留，完成后继续调度。自动保存停留在编辑页，新文章成功创建后更新为同一草稿地址。
- 手动保存成功后进入文章详情；再次编辑直接恢复源文。手动保存或提交发布期间禁止重复提交，并与自动保存互斥。
- 显示等待保存、保存中、已保存、保存失败、离线和冲突状态。普通失败暂停自动重试，提供重试按钮；恢复网络后重新调度。冲突必须先由作者处理，不静默覆盖服务器内容。
- 发布失败但草稿已保存时明确提示，并在重试时更新同一草稿，不重复创建。
- 离开未保存正文或发布设置时确认，刷新也提示未保存变更；加载失败不会把空表单覆盖到服务器或已有恢复副本。
- 可见范围只在提交发布时应用；组织已支持名称搜索和多选，失效或无权限目标需显式移除，目录失败不阻止草稿保存。见 [组织范围说明](organization-scope.md)。

## 当前标签页的恢复副本

未保存的正文、分类标签和发布范围使用 `sessionStorage` 保存恢复副本，按账号与文章／新建槽隔离；重新进入编辑页先提示“恢复”或“丢弃”，未经选择不会自动提交。恢复保留原修订号与创建幂等键，随后仍通过服务器并发检查。

- 最长保留 24 小时，每账号在当前标签页最多 5 份，优先清理较旧副本；读取或写入时清理过期、损坏、超限或字段不合法的数据。
- 普通刷新可恢复；关闭标签页、清理浏览器存储或存储配额不足可能失去副本，不保证跨设备或关闭浏览器后的恢复。存储失败时给出提示，编辑内容仍留在页面中。
- 主动退出、会话失效或跨标签页账号变化时清理恢复数据并中止旧会话请求；登录时移除其他账号的副本。同一账号普通刷新保留有效副本。
- 恢复内容是当前浏览器来源可读取的明文，未写入 `localStorage`，也不是加密保险库。需要跨设备恢复的内容必须先成功保存到服务器。
- 成功保存且没有后续未保存修改时清理对应副本；自动保存后仍未提交的发布范围可继续留在副本中。恢复副本的迁移失败不会删除唯一的旧副本。
