# 第五阶段：创作体验与内容可靠性

更新时间：2026-09-25。

## 范围与顺序

在本地 Java 17、PostgreSQL、Redis 开发环境继续迭代。每完成一个模块，前后端分别使用中文规范提交，推送 `codex/develop` 后通过 PR 合入 `main`，保留开发分支。

### 已完成：登录与权限收尾

- 请求绑定会话，隔离退出后的旧请求及过期 401；路由、读者创作入口、管理端角色隔离。
- 服务端草稿创建要求 AUTHOR 或 ADMIN，详见 `auth-hardening-status.md`。

### 已完成：文章编辑器第一模块

- 真正的 Markdown 安全渲染，预览与文章详情一致；源文可恢复、版本可持久化，兼容旧纯文本正文。
- 编辑／对照／预览视图，分类标签搜索选择，错误重试与未保存离开提醒。
- 手机对照布局改为上下排列，导航保持单行横向滚动。
- 接口及限制详见 `api/article-editor.md`。

### 已完成：组织范围选择

1. 基于现有部门、团队数据提供组织目录接口，不在前端写死组织名称。
2. 将目标组织 ID 输入替换为名称搜索和多选，展示当前可见范围摘要。
3. 服务端要求作者只能发布本人文章，并属于每一个目标组织；管理员可跨组织发布。提交时重新校验组织存在性，校验失败不写文章状态、审核单或 Outbox，保留原审核策略。
4. 覆盖全公司／部门／团队切换、无匹配结果、组织失效、跨组织越权和发布回归。详见 `api/organization-scope.md`。

### 下一模块：草稿自动保存与恢复

1. 明确自动保存状态、保存频率、失败重试和版本生成策略，防止每次按键都创建版本。
2. 设计并发修改检测，避免多个标签页或不同设备互相覆盖。
3. 正文不得跨账号复用；明确本地恢复数据的保留、退出清除及敏感内容边界。
4. 覆盖刷新、断网、退出、重登录和冲突处理后再交付。

- Java 17 Maven 全量回归：177 项，0 失败、0 错误、0 跳过；JDBC 测试使用 H2 PostgreSQL 兼容模式。
- 员工端 Vitest：55 项；管理端：37 项；两端 TypeScript 检查与 Vite 生产构建通过。
- Playwright：编辑器 9 项、认证边界 7 项与组织选择器 8 项，共 24 项通过；检查 1440px／390px 截图。
- 浏览器业务 API 使用测试桩；实际渲染、鉴权、源文持久化及版本恢复由后端 MockMvc/JDBC 测试验证。
- 本次未启动完整后端服务联调，也未运行依赖 Elasticsearch 的搜索端到端场景；未修改本机业务数据库。

## 暂不纳入

Docker、Nginx、正式部署、OIDC SDK 实接、附件基础设施、全文搜索基础设施仍不在本轮范围内。后续模块需逐项完成，不能把第一模块交付等同于第五阶段全部完成。
