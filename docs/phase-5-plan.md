# 第五阶段：创作体验与内容可靠性

更新时间：2026-09-30。

## 范围与顺序

在本地 Java 17、PostgreSQL、Redis 开发环境继续迭代。每完成一个模块，前后端分别使用中文规范提交，推送 `codex/develop` 后通过 PR 合入 `main`，保留开发分支。

### 已完成：登录与权限收尾

- 请求绑定会话，隔离退出后的旧请求及过期 401；路由、读者创作入口、管理端角色隔离。
- 服务端草稿创建要求 AUTHOR 或 ADMIN，详见 `auth-hardening-status.md`。

### 已完成：文章编辑器第一模块

- 真正的 Markdown 安全渲染，预览与文章详情一致；源文可恢复、版本可持久化，兼容旧纯文本正文。
- 编辑／对照／预览视图，分类标签搜索选择，错误重试与未保存离开提醒。
- 手机对照布局改为上下排列，导航保持单行横向滚动。
- 接口及限制详见 `api/article-editor.md`。

### 已完成：组织范围选择

1. 基于现有部门、团队数据提供组织目录接口，不在前端写死组织名称。
2. 将目标组织 ID 输入替换为名称搜索和多选，展示当前可见范围摘要。
3. 服务端要求作者只能发布本人文章，并属于每一个目标组织；管理员可跨组织发布。提交时重新校验组织存在性，校验失败不写文章状态、审核单或 Outbox，保留原审核策略。
4. 覆盖全公司／部门／团队切换、无匹配结果、组织失效、跨组织越权和发布回归。详见 `api/organization-scope.md`。

### 已完成：草稿自动保存与恢复

1. 有效草稿在停止输入 2 秒后自动保存，展示保存中、已保存、失败、离线和冲突状态；请求期间继续输入不丢失，手动保存与发布互斥，网络恢复重新调度，普通保存失败支持主动重试。
2. 新建草稿按作者与 `clientDraftId` 幂等创建。文章响应返回 `revision` 与 `updatedAt`，更新／发布必须携带 `expectedRevision`；数据库事务内锁行检查，过期且内容不同的请求返回 409，无状态、历史或 Outbox 副作用。
3. 自动保存只维护当前正文；手动创建、手动保存或提交发布时，与最近内容快照去重后新增历史。`revision` 与 `versionNo` 独立，内容或状态变化推进修订，相同内容重试不增加修订，必要时补齐手动快照。
4. 恢复副本使用当前标签页的 `sessionStorage`，按账号和草稿隔离，最长 24 小时、每账号最多 5 份。刷新后显式选择恢复或丢弃，退出、会话失效和跨标签页账号变化清理；本地存储不可用时提示，不阻断编辑。
5. 冲突时暂停自动保存，保留本地内容；查看服务器版本后选择保留哪份，继续提交仍检查最新修订。服务器已提交或不可编辑时禁止覆盖。
6. V8 为文章增加正数修订字段，旧数据默认 1。更新／发布新增必填参数，需与配套员工端同步升级，不能混用无修订保护的旧写服务。完整接口、迁移和恢复边界见 `api/article-editor.md`。
